#+title: cl-commonmark-gfm project plan
#+subtitle: Portable Common Lisp bindings for cmark-gfm
#+language: en
#+options: toc:3 num:t

* Purpose

Create =cl-commonmark-gfm=: a Common Lisp library that parses GitHub Flavored
Markdown (GFM) through [[https://github.com/github/cmark-gfm][cmark-gfm]], copies its native tree into a detached Lisp AST,
converts that AST to an HTML tree, and exposes cmark-gfm HTML and plain-text
rendering.  The initial implementation targets SBCL, CCL, and ECL on Linux and
macOS, amd64 and arm64 (CCL amd64 only; ADR-0001).  arm64 Linux is currently
unverified: CI is amd64-only (ADR-0013) and the maintainer's laptop is
macOS, so SBCL and ECL on arm64 are verified on the Mac only.  It is pinned
to cmark-gfm 0.29.0.gfm.13 (ADR-0002).

cmark-gfm is the syntax authority.  Lisp owns the durable AST, pure tree
operations, HTML-tree conversion, and public API.  This is not a Markdown
parser written in Lisp.

** Success criteria

- A user with only a system cmark-gfm package, a Lisp and ocicl can load the
  library and either get working results or a named project condition.  Never
  a crash, an unresolved symbol, or a silently loaded second core.
- No Markdown input crashes the process by itself: three limits keep cmark
  from aborting (ADR-0016), and an input guard rejects what triggers
  cmark's footnote-entity bug (ADR-0019).  On a machine already short of
  memory, cmark's allocator can still abort, and another bug in cmark's
  parser could still fault the process.
- Parse UTF-8 GFM to a Lisp value containing no native pointer; it remains valid
  after native resources are released.
- Preserve source positions and all semantic data needed for the HTML tree,
  including core GFM extensions.
- Render HTML and plaintext with the same enabled extension set used to parse.
- Share portable Lisp sources across SBCL, CCL, and ECL.
- Keep foreign calls, library loading, allocation, and cleanup in a small
  imperative shell; keep AST manipulation and HTML-tree conversion functional.

** Non-goals for version 1

- Writing or registering custom cmark syntax extensions from Lisp.
- Exposing mutable =cmark_node *= values through the ordinary API.
- A lossless Markdown formatter/editor model.
- Replacing cmark-gfm's HTML renderer: =markdown->html= stays native.  The
  HTML tree is tested against it (ADR-0011), not substituted for it.
- Downloading or compiling C dependencies when the Lisp system is loaded.  The
  project compiles no C at all (ADR-0008).
- Windows (ADR-0001).

* Core architectural decision

** Functional core, imperative shell

#+begin_example
Markdown
   |
   v
imperative shell: encode -> parse -> traverse/copy -> release
   |
   v
functional core: AST -> transform AST -> HTML tree -> string
   |
   +--> imperative shell: parse -> render -> copy -> free
#+end_example

The parser operation necessarily allocates native state and can signal a
loading/ABI error.  Its high-level interface is still value-oriented:
=parse= returns a fresh, detached AST or signals a project condition.  It never
returns a live cmark handle.

The core gets and returns ordinary Lisp values only.  It is deterministic,
portable, straightforward to test without native libraries, and suitable for
persistent-style rewrite functions.  The shell owns native lifetimes and
concentrates all effects in one reviewable place.

** AST contract

Use a compact, immutable-by-convention representation.  A suitable initial
implementation is a =node= structure whose constructor is private and whose
public package exports no mutators:

#+begin_src lisp
(defstruct (node (:constructor %make-node) (:copier nil) (:conc-name %node-))
  (kind nil :read-only t)
  (attributes nil :read-only t) ; canonical plist
  (children nil :read-only t)   ; proper list of NODE
  (sourcepos nil :read-only t))
#+end_src

=:copier nil= leaves the name =copy-node= to the schema-checked copier below.
The =%node-= readers stay internal, because =node-attributes= and
=node-children= return copies.

The representation is not the public promise.  The promise is constructors,
predicates, read-only queries, structural equality, and pure transforms.  This
permits a later move to specialized node structures without an API break.
=cl-commonmark-gfm.ast= exports:

#+begin_src lisp
(make-node kind &key attributes children sourcepos)
(copy-node node &key attributes children sourcepos)
(node-p object)
(node-kind node) (node-attributes node) (node-attribute node key)
(node-children node) (node-sourcepos node)
(node= a b &key (sourcepos t))
(walk-ast function node)               ; :enter and :exit calls, depth-first
(fold-ast function initial-value node) ; depth-first, parent before children
(map-ast function node)                ; the results, in the same order
(transform-ast function node)          ; bottom-up rebuild
#+end_src

- *One schema table,* one row per vocabulary kind, drives all validation.  It
  gives each attribute a type and a default, or marks it required, and says
  whether the kind is a leaf.  Required: =:level= (1–6), both footnote kinds'
  =:label= (a non-empty string) and =:type-name=.  The one rule outside the
  table: an =:ordered= list needs an integer =:start= and a non-=nil=
  =:delimiter=, and a =:bullet= list has neither.
- =make-node= checks the kind, the attribute plist (known keys, none
  repeated, values of the right type, required keys present) and the
  children (a proper list of nodes, empty for a leaf).  It fills missing keys
  from their defaults and stores every key in schema order, so equal nodes
  have =equal= attributes.
- =copy-node= merges =attributes= over the node's own, and replaces
  =children= and =sourcepos= only when they are supplied (=:sourcepos nil=
  clears it).  The result is checked like a new node; the kind never changes.
- =node-attributes= returns a fresh copy, and =node-children= a fresh list; a
  node stores a copy of the children it is given.  =node-attribute= signals
  for a key the kind doesn't have, rather than returning =nil= for a typo.
- =node== compares kind, attributes, children and, unless =:sourcepos nil=,
  source positions.  Strings compare case-sensitively, which rules out
  =equalp=.
- =walk-ast= calls =function= with =:enter= and =:exit= for each node,
  depth-first; an =:enter= call that returns =:skip= skips the node's
  children and its =:exit=.  It reads child lists without copying.  It is
  the one AST traversal: =fold-ast=, =map-ast=, =transform-ast= and the HTML
  tree's AST walks are built on it.  No walk over an AST or an HTML tree
  recurses on its depth (ADR-0015).
- =transform-ast= gives =function= each node with its children already
  transformed.  It returns a node, a list of nodes (spliced into the parent)
  or =nil= (deleted); the root must come back as exactly one node, bare or
  alone in a list.  Rebuilt nodes are checked.
- A broken rule signals =invalid-ast-node=.  Not checked: which kinds nest
  inside which, or whether a node is block or inline.  cmark promises neither,
  and conversion renders whatever it is given.

Use stable Lisp keywords, not cmark's integer node IDs or type strings.  The
vocabulary below was verified against cmark-gfm 0.29.0.gfm.13 (ADR-0005;
=tests/fixtures/vocabulary.md=, =make check-vocabulary=).

  label as written (ADR-0018).
- =custom_block= / =custom_inline= never come from parsing and are not in the
  vocabulary; meeting one signals =unsupported-extension-node=.

*** Source positions

Copy source positions only from a parse with =CMARK_OPT_SOURCEPOS=
(=:sourcepos t=, =parse='s default).  Without it, positions after a
multi-line code span or raw HTML drift, so =:sourcepos nil= gives no
positions at all (ADR-0018).  Copy them as
=((start-line . start-column) . (end-line . end-column))=, or =nil= when
cmark reports none (a start line of 0: softbreaks, linebreaks and email
autolinks).  They are reported as-is and never repaired: cmark emits
end-before-start ranges, zero end columns and children that start before
their parent.  Inside a paragraph the table extension rebuilt, inline
positions are wrong, and can be negative (M3 finding 7).  =make-node= checks
only their shape (integers, possibly negative) and accepts inverted ranges.
cmark's columns are bytes; the API must not imply Unicode grapheme-column
semantics.

Unknown extension nodes must not disappear.  Represent a recognized but
otherwise unsupported extension as =:extension= with its type string, source
position, safely copied attributes, and children.  cmark has no public getter
for an extension's name, so =:extension-name= is =nil=; since only the five
core extensions are ever attached, this node cannot occur in a parse under
the pin (ADR-0008).  M3 tests it on nodes built through cmark's public API.
If even that cannot be represented safely, signal
=unsupported-extension-node=.

* FFI architecture

** CFFI is the portable Lisp frontend

CFFI is the one Lisp FFI API used by the project.  It binds cmark-gfm's public
API directly (next section); the project compiles no C.  That API is well
suited to CFFI: opaque pointers, scalar integers, =size_t=, and byte strings.
No version-1 operation needs a callback, a variadic function, or a C structure
passed or returned by value.  The one structure read from Lisp is the default
allocator, as an array of function pointers (ADR-0008).

Use exact ABI types:

- =size_t= becomes CFFI =:size=, =int= becomes =:int= and =uint16_t= becomes
  =:uint16=.  Every pointer is =:pointer=.
- C option bitsets are =int=, as the header declares them.
- C boolean-like =int= is explicitly decoded to Lisp =t=/=nil=.
- Strings cmark lends come back as pointers, and are decoded explicitly, as
  UTF-8.
- A C =bool= return is declared =:uint8= and tested against zero, so only its
  defined byte is read (ADR-0008).
- UTF-8 source is an octet vector plus its byte length, never a Lisp character
  count.
- The portable sources do not use =sb-alien=, CCL-specific foreign APIs, or
  ECL's =ffi:= package.

** Direct binding

=cl-commonmark-gfm/native= binds =libcmark-gfm= and =libcmark-gfm-extensions=
through CFFI, with no project C library in between (ADR-0008).  Every job needs
a public entry point of 0.29.0.gfm.13:

| Job | Public API |
|-----+------------|
| Register core extensions | =cmark_gfm_core_extensions_ensure_registered=, once per process, under a lock |
| Attach the selected extensions | =cmark_find_syntax_extension= + =cmark_parser_attach_syntax_extension= |
| Extension list for HTML rendering | =cmark_parser_get_syntax_extensions(parser)=; the parser outlives rendering |
| Free render output | the =free= slot of =cmark_get_default_mem_allocator()= |
| Classify nodes | pure Lisp over the type code, extension identity and type string |
| Table and task metadata | =cmark_gfm_extensions_get_table_alignments=, =…_get_table_columns=, =…_get_tasklist_item_checked=; the header row is known by its type string |
| Version probe | =cmark_version_string()=, and =cmark_version()= for the number check (ADR-0009) |

The functions =/ffi= declares are listed in the
[[file:2026-09-30-m2-native-layer-design.md][M2 design]], §5.1.

The default =:gfm= profile attaches tables, strikethrough, autolinks, tag
filter, and task lists, plus the =CMARK_OPT_FOOTNOTES= option (ADR-0006).  Tag
filter changes HTML rendering only; the AST still holds the filtered raw HTML
(ADR-0005).

*Classification.*  The shell reads three facts per node and hands them to the
pure =classify-node (type-code extension type-string)=:

1. =cmark_node_get_type=, an integer;
2. which cached core-extension pointer (=table=, =strikethrough=, =autolink=,
   =tagfilter=, =tasklist=) equals =cmark_node_get_syntax_extension=, or =nil=;
3. =cmark_node_get_type_string=.

No extension: the core type code decides (the constants are transcribed from
=cmark-gfm.h= and checked against the pinned header in =vendor/cmark-gfm=,
ADR-0011).  =table=: the type string decides the four table kinds.
=strikethrough=: =:strikethrough=.  =tasklist= on =CMARK_NODE_ITEM=:
=:task-item=.  Any other extension node: =:extension=.  Type strings alone are
not enough: in 0.29.0.gfm.13 =cmark_node_get_type_string= returns
="<unknown>"= for both footnote kinds.

*Two ABI beliefs* replace checks a C compiler would have made; each has a test
and ADR-0008 says what the test cannot catch:

1. The allocator's =free= is its third function pointer, read as
   =(cffi:mem-aref allocator :pointer 2)=.  A test asserts the three slots are
   non-null and distinct.  That misses a reordering.  Calling another slot
   as =free= is undefined behavior: on SBCL 2.6.4 x86-64 the native suite
   dies at its first render, and elsewhere a reordering could leak
   silently.
2. The tasklist accessor's C =bool= is one byte (see ABI types above).

Do not bind cmark internal headers, =cmark_llist= internals or extension
private data, and do not use dynamically assigned extension node IDs.  A shim
comes back only for a need no public entry point meets, or a failed ABI
belief, and is recorded in an ADR first (ADR-0008).

** Ownership protocol

The normal parse path is:

#+begin_src lisp
(defun parse (markdown &rest options)
  (check-type markdown string)
  (let ((checked (check-options :parse 'parse options)))
    (check-input markdown checked 'parse)
    (with-native-state (state)
      (with-native-document (document markdown checked :state state)
        (copy-native-tree document checked 'parse)))))
#+end_src

=check-options= is the pure step described under "Options", and
=check-input= applies the input limits (ADR-0016) and the input guard
(ADR-0019).  Both run before =with-native-state=, which starts cmark on the
first call (ADR-0017), so a bad option, an oversized input or one the guard
rejects fails before any native call.  =with-native-state= then holds the
state until the document is released, so cmark is never closed under the
parse (ADR-0017).

A =native-document= handle owns one =cmark_parser *= and its finished root,
together:

- *Parse:* =cmark_parser_new(options)=; attach the selected extensions;
  =cmark_parser_feed(bytes, length)= with the octet vector pinned for that
  call only; =cmark_parser_finish= → root, under the finish lock
  (ADR-0017).  A null parser or root signals =native-parse-error=.
- *Render:* =cmark_render_html= (passing
  =cmark_parser_get_syntax_extensions(parser)=) or =cmark_render_plaintext=,
  while the handle is alive.  A null buffer signals =native-render-error=.
- *Release:* =with-native-document= is an internal =unwind-protect= resource
  scope.  It clears the document's alive flag, then calls
  =cmark_node_free(root)=, then =cmark_parser_free(parser)=, each exactly
  once, on success, condition, and non-local exit.  Every native accessor
  checks the alive flag, so a document used after its scope signals instead
  of touching freed memory (ADR-0017).

=copy-native-tree= eagerly copies every string and scalar, then returns a pure
AST.

Ownership rules:

- A native node is borrowed from its document and dies with that document.
- A C string returned by a cmark accessor is borrowed; convert it before
  freeing the document or issuing an operation that may invalidate it.
- A render result (=cmark_render_*=) is owned by the caller.  Copy it, then
  free it only through the =free= slot of =cmark_get_default_mem_allocator()=.
- Never call =cffi:foreign-free= on cmark-owned output.  The wrong allocator
  can corrupt the heap.
- Retain the UTF-8 octet vector for the entire foreign call.  A raw address may
  not outlive its dynamic pointer scope.
- Null is an optional value only where =cmark-gfm.h= documents it; elsewhere it
  becomes a typed condition before any accessor call.
- The native layer counts live parsers, roots and render buffers.  Every
  native test suite asserts all three are zero when it ends; this is the leak
  check.
- A finalizer may be an emergency leak backstop, never normal cleanup.
- Every cmark call runs with interrupts deferred, so an interrupt, such as
  a timeout, lands when the call returns, never inside cmark's allocator.
  Timeouts are coarse as a result (ADR-0017).

** Library discovery and initialization

Discovery loads the exact pinned pair by absolute path; there is no bare-name
=dlopen= (ADR-0009).  =resolve-cmark-libraries= is pure: its filesystem access
is passed in, so every branch is tested against synthetic listings.

1. *Override.*  =*cmark-gfm-libraries*= if non-=nil=, else the environment
   variable =CL_COMMONMARK_GFM_LIBS=.  The value is two absolute paths
   (=core:extensions= in the variable, a two-element list in the special),
   used verbatim; both must exist as regular files.  There is no fallback: a
   wrong override, including an empty-but-set variable, signals
   =native-library-not-found= naming the override and the failing path.
2. *Directory search.*  Otherwise walk a fixed list; the first directory
   holding *both* pinned files wins.  A directory holding only one is
   skipped, never paired with another, so the extensions library cannot pull
   a second core into the process.

   | OS | Directories, in order | Core / extensions filenames |
   |----+-----------------------+-----------------------------|
   | Linux | =/usr/lib/<multiarch>=, =/usr/lib64=, =/usr/lib=, =/usr/local/lib= | =libcmark-gfm.so.0.29.0.gfm.13= / =libcmark-gfm-extensions.so.0.29.0.gfm.13= |
   | macOS | =/opt/homebrew/lib=, =/usr/local/lib= | =libcmark-gfm.0.29.0.gfm.13.dylib= / =libcmark-gfm-extensions.0.29.0.gfm.13.dylib= |

   =<multiarch>= is =x86_64-linux-gnu= or =aarch64-linux-gnu=.  Only the
   versioned names match (on Debian the unversioned symlinks come only with
   the =-dev= packages).  Nothing found signals =native-library-not-found=,
   listing every directory searched and the override variable's name.
3. *Load and verify.*  Load the core, then the extensions, by absolute path.
   =cmark_version_string()= must equal ="0.29.0.gfm.13"=, then
   =cmark_version()= must equal =#x001D000D=, the pin as a number; else
   =native-abi-mismatch= with both versions.  Register the core extensions,
   and cache the five extensions and the allocator's =free=.  Smoke-parse a
   table, a checked task item and a footnote under =:gfm=; they must classify
   to =:table=, =:task-item= and =:footnote-reference=, else
   =native-initialization-error=.

Startup ([[file:2026-09-30-m2-native-layer-design.md][M2 design]] §5.2) runs
on the first call that needs cmark, once per process, under a lock
(ADR-0017).  A failed attempt closes what it loaded and publishes nothing,
so the next call tries again.  Trying again is unsafe while something else
in the process keeps libcmark-gfm loaded.  Before an image is saved, the
Lisps' own save hooks close both libraries and clear the state, so a saved
image starts up again wherever it runs.  While any call holds the state,
they close nothing, and the save fails instead.  If a save goes ahead
anyway, a restore hook clears any published state when the image starts
(M2 design §5.3).

The Guix container sets =CL_COMMONMARK_GFM_LIBS= to its profile's two
versioned paths; its =LD_LIBRARY_PATH= is for ocicl's =libcrypto= only
(ADR-0004).

* Runtime-specific CFFI behavior

** Shared policy

Do not make CFFI Groveler a required user load-time dependency in version 1.
It would require a C toolchain and headers merely to load Lisp.  The project
compiles no C; the runtime version check, the smoke parse, the ABI-belief
tests and the header-constant check against =vendor/cmark-gfm= guard against
ABI drift.  A Groveler-based developer check may be added later.

No reader conditionals belong in AST or HTML-tree code.  In the library they
appear only in =/native=: the save and restore hooks, deferring interrupts,
and ECL's =:dffi= check (ADR-0017).
If a loader workaround is needed, confine it there and cover it with an
integration test.

** SBCL

SBCL is the initial development target.  Standard CFFI dynamic loading supports
the required opaque-pointer API.  It may also support statically linked
deployment, but that is an application delivery mode, not a library assumption.

- Do not use =sb-alien= in library sources.
- Do not rely on finalizer timing or a GC run for native cleanup.
- Keep source octets live for every call and do not retain raw addresses.
- Version 1's no-callback policy avoids callback support differences.
- A function on =sb-ext:*save-hooks*= closes both libraries before an image
  is saved, and one on =sb-ext:*init-hooks*= clears any published state
  when an image starts (ADR-0017).
- Each cmark call runs inside =sb-sys:without-interrupts= (ADR-0017).

** CCL

CCL uses CFFI through its implementation backend; it needs no separate FFI
definitions for this API.  CCL 1.13 has no arm64 build on any OS, so it runs
on amd64 only: Linux in CI, and macOS by hand on Intel or under Rosetta with an
x86_64 cmark-gfm (ADR-0001).  The major practical risk is dynamic-loader
configuration on macOS.

- Exercise both the override and the directory search, in Linux CI and in the
  manual macOS run.
- Do not retain implementation-owned string storage across a foreign call.
- Keep all loader branches inside the native shell; AST/HTML-tree code stays
  completely shared.
- A function on =ccl:*save-exit-functions*= closes both libraries before an
  image is saved, and one on =ccl:*restore-lisp-functions*= clears any
  published state when an image starts (ADR-0017).  Both are first
  exercised in M4.
- Each cmark call runs inside =ccl:without-interrupts= (ADR-0017).

** ECL

without it, CFFI's normal =load-foreign-library= route cannot load a library.

- Detect missing =:dffi= and signal =dynamic-ffi-unavailable=, before
  discovery, with static-link instructions rather than a generic
  unresolved-library failure.
- Document a deployment path that links cmark-gfm into the ECL application,
  then uses ECL's supported static foreign-library mechanism.
- Maintain the dynamic-FFI ECL step in CI's one job (ADR-0013) and, after it
  stabilizes, a compiled static-link smoke test.
- The pure core continues to load and test with no ECL FFI configuration.

* C safety and security

** ABI and memory safety rules

- Load only the pinned core/extensions pair, from one directory, by absolute
  path (ADR-0009).  Any other runtime version signals =native-abi-mismatch=.
  Do not call an arbitrary system cmark library supported.
- No Lisp dereference of a cmark structure, except the default allocator's
  =free= slot (ADR-0008): every other C structure remains opaque.
- Check every status and pointer result before access.
- Use =size_t= end-to-end.
- No input reaches cmark past the three limits, each checked before cmark
  does the work it guards (ADR-0016), or past the input guard, which
  rejects what triggers cmark's footnote-entity bug when footnotes are on
  (ADR-0019).
- Hold the finish lock around =cmark_parser_finish=: it writes cmark's
  global tables, and concurrent parses would corrupt each other (ADR-0017).
- Copy render output before freeing it through the allocator's =free= slot.
- Do not allow C callbacks into Lisp in v1: that avoids foreign-thread entry,
  callback rooting/lifetime, and exceptions crossing C frames.
- Do not expose cmark mutation functions in v1.  The AST is a read model; C
  mutation creates aliasing and ownership cases without serving the goal.
- There is no sanitizer or Valgrind gate: the project compiles no C, and the
  Lisp runtimes' collectors use signals and memory protection.  Native memory
  safety is checked by the live-handle counters, parse/render cycles under GC
  pressure, and render stress tests (ADR-0013).

** Rendering policy

cmark-gfm's default HTML behavior treats raw HTML and unsafe link schemes
safely; =CMARK_OPT_UNSAFE= deliberately turns that off.  The Lisp API exposes
this only as =:unsafe-html= and never enables it by default.

The HTML tree is a separate security boundary.  =ast->html-tree= applies these
policies (ADR-0012):

- =:raw-html :omit= (default) replaces each =:html-inline= / =:html-block= with
  =(:*comment* nil " raw HTML omitted ")=.
- =:raw-html :text= emits the literal as an ordinary, escaped string.
- =:link-policy :safe= (default) blanks a link =href= or image =src= that
  starts, case-insensitively, with =javascript:=, =vbscript:=, =file:= or
  =data:=, except =data:image/png=, =gif=, =jpeg= and =webp=, as cmark does.
  =:unsafe= keeps every URL.

There is no trusted raw-HTML mode: a caller who needs the markup reads
=:literal= from the AST.  A copied AST is not a sanitized AST.  The
=tagfilter= extension does not help here: it changes cmark's HTML output only,
and the AST keeps =<script>= blocks verbatim.  =html-tree->string= always
escapes, but does not check URLs added to a tree after conversion.

** Conditions

| Condition | Meaning |
|-----------+---------|
| =invalid-option= | the parent of the two below |
| =invalid-parse-option= | a bad parse option; =parse= signals it for every option problem |
| =invalid-render-option= | from a renderer or =ast->html-tree=: a bad render or tree option, an unknown key, an odd-length list |
| =resource-limit-exceeded= | an input, its nodes or its output would pass one of the three limits (ADR-0016) |
| =unsupported-input= | with footnotes on, a =[= followed by an entity that decodes to =^=: cmark-gfm can't parse it safely (ADR-0019) |
| =native-error= | the parent of the six below |
| =native-library-not-found= | the pinned core/extensions pair could not be found or loaded |
| =native-abi-mismatch= | the runtime cmark-gfm version is not the pin, or asking the library for it failed |
| =dynamic-ffi-unavailable= | ECL requires its static deployment route |
| =native-initialization-error= | startup failed after the version check: an extension or the allocator's =free= is missing, a call into the loaded libraries failed, or the smoke parse failed in any way |
| =native-parse-error= | a document could not be produced |
| =native-render-error= | a renderer could not produce a buffer |
| =unsupported-extension-node= | no safe semantic AST mapping exists |
| =invalid-ast-node= | a node, attribute key or transform result breaks the AST schema |
| =invalid-html-tree= | =html-tree->string= was given a malformed node |

All are subtypes of =commonmark-gfm-error=, an =error=, and report
"operation: reason: datum"; every slot defaults to =nil=.
=resource-limit-exceeded= adds the limit's variable and its effective
maximum; the native ones add the override, the paths or directories tried,
and the versions.  A native document used after release signals an internal
condition that isn't exported.  Raw CFFI errors are implementation details,
not the routine public vocabulary.  Each condition's slots and causes:

* Functional AST and HTML tree

** Options

Every entry point takes its options as a =&rest= list and checks them by
hand, before any native call (ADR-0014, ADR-0017).  =check-options=, pure, in
=/native-core=, resolves each option to its value or its default.  An
odd-length list, an unknown key, a bad value, or a repeated or unknown
extension signals; when a key repeats, the leftmost value wins, but every
value must be valid.  The parse, HTML and plaintext option bits follow from
the checked options, and rendering always carries the parse's bits
(ADR-0006).

The default =:gfm= profile attaches the five core extensions and turns
footnotes on; =:commonmark= attaches none and leaves footnotes off.  The
profile only supplies defaults: an explicit =:extensions= or =:footnotes=
overrides it.  The parse's options are stored on the =:document= node, so
consumers can tell syntax that didn't match from an extension that was off.

Each option's values, its default per entry point, the condition a bad one
signals, and the option bits:
[[file:2026-09-30-m2-native-layer-design.md][M2 design]] §7.2 and §7.3.

** Native-to-Lisp copier

=copy-native-tree= is the sole impure AST stage (ADR-0018).  It walks the
native tree with the one native walker (=cmark_node_first_child=,
=cmark_node_next= and =cmark_node_parent=, with its own stack and no
=cmark_iter=), copies values through cmark's public accessors, classifies
each node with the pure =classify-node= (ADR-0008), and builds the AST
bottom-up through =make-node=.  It copies every node kind, and counts nodes
against =*max-nodes*= (ADR-0016).  Its attributes, positions and text
follow the M2 design's §6.3 to §6.5, and four oracles check it over the
whole corpus (see Tests).

Its default behavior is not data loss: emit =:extension= if it can safely
identify the foreign extension; otherwise signal =unsupported-extension-node=.
An =:extension= node cannot occur in a parse under the pin (ADR-0008), so
M3 tests this path on nodes built through cmark's public API.

** HTML tree contract

=ast->html-tree= is pure and does no FFI.  The tree has the LHTML shape
(closure-html's convention), not SXML: attributes are always the second
element (ADR-0010).

#+begin_example
(tag attrs child ...)          ; tag: keyword; attrs: nil or ((:name "value") ...)
(:*comment* nil " text ")      ; comments use the same three-part form
#+end_example

- Attributes appear in the order cmark emits them.  Each child is a string
  (unescaped text) or an element.
- A document yields a list of top-level elements and strings.
  =:document-wrapper= (a non-void element keyword, default =nil=) wraps them
  as =(wrapper nil ...)=.  A root that isn't a =:document= converts as a
  document's only child.
- No source positions and no =data-*= metadata beyond what cmark's own HTML
  emits; source positions live in the AST.

*Layout lives in the tree* (ADR-0014).  The converter emits a ="\n"= string
wherever cmark's renderer writes a newline.  Where cmark calls =cr=
(=cmark_html_render_cr=), it emits ="\n"= unless the output so far is empty or
already ends in a newline.  Children are normalized: adjacent strings are
merged and empty strings dropped.  So a tight task item is
=(:li nil (:input ((:type "checkbox") (:disabled ""))) " open task")=, and a
=:linebreak= is =(:br nil) "\n"=.

Each node takes the shape cmark 0.29.0.gfm.13's HTML renderers produce under
the options in effect; the oracle settles every detail (ADR-0011).  The table
leaves out the newlines around block elements.

| AST | HTML tree |
|-----+-----------|
| =:paragraph= | =(:p nil ...)=; unwrapped inside tight lists, as cmark does |
| =:heading= | =(:h1 nil ...)= through =(:h6 nil ...)= |
| =:link= | =(:a ((:href "...") (:title "...")) ...)=; =href= carries cmark's percent-encoding; no =title= pair when it is =""= |
| =:image= | =(:img ((:src "...") (:alt "...") ...))=; =alt= is the plain text of every literal under it, raw HTML included, with breaks as spaces; a dangling footnote reference adds =[^label]= |
| =:table= | =(:table nil ...)=: =:thead= wraps the =:table-header= row, =:tbody= the =:table-row= rows; =align= from each cell's =:align= |
| =:task-item= | =(:li nil (:input ((:type "checkbox") (:checked "") (:disabled ""))) " " ...)=; no =:checked= pair when unticked; no =task-list-item= class |
| =:footnote-reference= | =(:sup ((:class "footnote-ref")) (:a ((:href "#fn-L") (:id "fnref-L") (:data-footnote-ref "")) "N"))=: L is the label, percent-encoded, and N the definition's number.  The k-th reference to a definition has the id =fnref-L-k=.  A reference with no definition is the text =[^label]= |
| footnote definitions | moved to one section at the end: =(:section ((:class "footnotes") (:data-footnotes "")) (:ol nil (:li ((:id "fn-L")) ...)))=, with back-references.  Only one definition per label counts, the first the walk leaves (cmark's registration order), and only if a reference resolves to it.  Numbered in definition order (ADR-0014) |
| =:softbreak= | =:softbreak= policy: ="\n"=, =" "= or =(:br nil) "\n"= |
| raw HTML | =:raw-html= policy (see Rendering policy) |
| =:extension= | signals =unsupported-extension-node=; cannot occur in a parse under the pin (ADR-0008), so M3 tests it on nodes built through cmark's public API |

=ast->html-tree= takes its options as =&rest= and validates them by hand
before converting anything (ADR-0014).  An odd-length list, an unknown key, a
value outside the table below, or a =:document-wrapper= that isn't a non-void
element keyword signals =invalid-render-option=.  A repeated key: the leftmost
value wins, as with =&key=, but every value must be valid, so
=:softbreak :space :softbreak :bogus= signals =invalid-render-option=.

| Option | Values (default first) | cmark equivalent (oracle) |
|--------+------------------------+---------------------------|
| =:raw-html= | =:omit=, =:text= | =:omit= = default safe HTML; =:text= has direct tests |
| =:softbreak= | =:newline=, =:space=, =:br= | default, =CMARK_OPT_NOBREAKS=, =CMARK_OPT_HARDBREAKS= |
| =:link-policy= | =:safe=, =:unsafe= | default; =CMARK_OPT_UNSAFE= for links only |
| =:document-wrapper= | =nil= or a non-void element keyword | none |

=html-tree->string= is the public, pure serializer (ADR-0010, ADR-0014):

- *Exact for any tree; layout lives in the tree.*  Its output is the plain
  concatenation of what the tree holds: it adds no newlines.  A tree from
  =ast->html-tree= prints as cmark's HTML.
- *Always escapes* text, comment text and attribute values (=&=, =<=, =>=,
  ="=) exactly as houdini does; nothing is emitted raw.  In =href=, =src= and
  =id= values, ='= also becomes =&#x27;=.  URLs are only entity-escaped, since
  the tree already carries cmark's percent-encoding.
- *Bare attributes:* =data-footnotes=, =data-footnote-ref= and
  =data-footnote-backref= print with no value when it is =""=.  Every other
  attribute prints as ~name="value"~, so the checkbox keeps ~checked=""~ and
  ~disabled=""~.
- *Void elements:* =br=, =hr=, =img= and =input= print as =<br />=,
  ~<img src="…" alt="…" />~ and so on.
- *Comments:* =(:*comment* nil "text")= prints as =<!--text-->=, its text
  escaped like any other text.
- Names print lowercase, and are classified by that lowercased string, so
  =:|href|= is =:href= and =:|br|= is =:br=.
- *Validates* its input.  These signal =invalid-html-tree=, naming the node: a
  malformed element; a tag or attribute name not matching =[a-z][a-z0-9-]*=
  once lowercased (=:*comment*= is the one exception); a non-string attribute
  value; a void element with children; a comment that isn't exactly
  =(:*comment* nil "text")=, or whose text contains =--=, starts with =>= or
  =->=, or ends with =-=.  A tag alone, =(:p)=, reads as =(:p nil)=.
- Unknown but valid tags are allowed.
- It does not sanitize URLs; =:link-policy= applies inside =ast->html-tree=.

* Public API sketch

#+begin_src lisp
(parse markdown &rest options)
;; string -> :document AST
;; options: :profile :extensions :footnotes :smart :sourcepos (default t)

(markdown->html markdown &rest options)
;; string -> string, from cmark's HTML renderer
;; options: :profile :extensions :footnotes :smart :sourcepos (default nil)
;;          :softbreak :unsafe-html

(markdown->plaintext markdown &rest options)
;; string -> string, from cmark's plaintext renderer
;; options: :profile :extensions :footnotes :smart :softbreak :width

(markdown->html-tree markdown &rest options)
;; string -> HTML tree: (ast->html-tree (parse …) …), parsed without positions
;; options: :profile :extensions :footnotes :smart, and the tree options

(ast->html-tree node &rest options)
;; options: :raw-html :softbreak :link-policy :document-wrapper, checked by hand
;; AST -> HTML tree (list of nodes, or one wrapper element)

(html-tree->string tree)
;; HTML tree -> string; adds no layout, so a converted tree prints as cmark's HTML

(walk-ast function node)
(map-ast function node)
(fold-ast function initial-value node)
(transform-ast function node)
;; pure structural utilities (see AST contract)

*max-input-octets* *max-nodes* *max-output-octets* ; the limits (ADR-0016)
*cmark-gfm-libraries*                              ; the override (ADR-0009)
#+end_src

=cl-commonmark-gfm= exports all of these (ADR-0017).  MARKDOWN is a string;
anything else signals a =type-error=.  Each entry point checks all its
options before any native call, then applies the limits and the input
guard (ADR-0019), then starts cmark if needed.  Options, values and defaults:
[[file:2026-09-30-m2-native-layer-design.md][M2 design]] §7.2.

Do not silently ignore renderer options.  Passing HTML-tree-only options to
=markdown->html= signals =invalid-render-option=.

* Build, testing, and release

** Native dependency policy

Phase 1 supports an externally installed cmark-gfm runtime package: the two
versioned shared libraries, no =-dev= package or C toolchain needed.  It must
report the pinned version (ADR-0002): Debian trixie ships it; the Guix
container provides it; the maintainer's macOS install is checked by hand.
Startup verifies the core library, the extensions library and the runtime
version separately (ADR-0009).  Failing clearly is preferable to silently
loading plain cmark.

Phase 2 may provide reproducible bundled-source artifacts, pinned to a specific
upstream revision and recording compiler/architecture/library version.  It
supplements; it does not replace; the external-library path.  Since the
project compiles no C today, it needs its own ADR.

** Tests

Tests use Parachute (ADR-0007), installed through ocicl.  Each suite runs with
the quiet reporter and turns the result into the process exit code, so CI and
=make= see failures without parsing output.

Pure tests:

- AST construction/query/rewrite invariants and structural equality: every
  schema rule, =copy-node=, =node-attribute=, =node== and the three
  transforms.
- =classify-node= and =resolve-cmark-libraries= over synthetic inputs.
- *Oracle fixtures* (ADR-0014): hand-built ASTs checked against the pinned
  CLI's HTML.  =tests/fixtures/html/cases= lists one case per line,
  =name file.md cmark-flags…=; =tests/fixtures/html/name.html= is the CLI's
  output for it, committed.  =make check-fixtures= re-runs the CLI for every
  case and diffs.  =make fixtures-html= writes only the missing files, and
  never overwrites one.  In Lisp, each case's
  =(html-tree->string (ast->html-tree ast …))= must equal its file, and the
  Lisp cases and the manifest must name exactly the same set.  The cases
  cover every node kind but =:extension=, every mapping row, both non-default
  softbreaks, both link policies (=:unsafe= only without raw HTML),
  percent-encoding and the footnote rules.
- Direct tests where cmark has no equivalent: =:raw-html :text=,
  =:document-wrapper=, the footnote pre-pass on hand-built ASTs, and every
  =invalid-render-option=, =invalid-html-tree= and
  =unsupported-extension-node= case.
- Converting twice gives =equal= trees, and a tree holds nothing but lists,
  strings and keywords.
- Trees 100,000 levels deep and 300,000 children wide go through every walk
  (ADR-0015).
- *The native layer's pure parts:* cmark's constants against
  =vendor/cmark-gfm/src/cmark-gfm.h=, read as text; every option and bad
  value of each entry point, and their bits; the limits' effective maxima,
  the table-cell bound and the output bounds' per-node terms; the input
  guard's matches and near misses; the UTF-8 encoder, and the decoder
  against the Unicode Standard's well-formed sequences and its
  maximal-subpart examples; the corpus reader's counts.
- *The UTF-8 property* (ADR-0020): =decode-utf8= never signals on random
  octets, and what it returns survives encoding and decoding again.
- *Purity:* =make check-purity= runs the pure suite on SBCL, CCL and ECL,
  each even if an earlier one failed, and fails if a =CFFI= package exists
  after the run.

Native tests, on SBCL (CCL and ECL join in M4):

- *The corpus:* a pure reader of =vendor/cmark-gfm/test/*.txt= mirrors
  =spec_tests.py=.  It gives 747 enabled examples in six files, each with its
  file's base options.
- *Four oracles* (ADR-0011, ADR-0018), the first three over the corpus:
  1. cmark's expectations: =markdown->html= with =:unsafe-html t= reproduces
     the expected HTML byte for byte, on 741 examples;
  2. the HTML oracle: =(html-tree->string (markdown->html-tree md …))=
     equals =(markdown->html md …)= under each =:softbreak= value;
     =:link-policy :unsafe= is compared with =:unsafe-html t= only on
     examples without raw HTML;
  3. the XML oracle: a test-only writer prints the copied AST in cmark's
     XML, which must equal =cmark_render_xml= of the same document;
  4. the fixture ASTs: each of the 28 cases, parsed, equals its hand-built
     AST.

  Direct tests cover what no corpus-wide witness sees in the AST itself:
  labels as written, body-cell alignment, the document's attributes and
  =:sourcepos nil=.  ADR-0014's two footnote divergences are pinned
  directly, each by a minimal input whose tree-path HTML is asserted
  exactly; a corpus example that hits one is listed by name, and must keep
  differing (ADR-0018).
- *Crash guards* (ADR-0016): crafted inputs for each source of blowup are
  rejected with =resource-limit-exceeded= before cmark does the work; below
  the limits, no bound undercounts.
- *The input guard* (ADR-0019): each entity form is rejected through every
  entry point, before any parser is created; near misses parse; with
  footnotes off, the rejected inputs parse.
- *Four properties* (ADR-0020) over generated Markdown: the HTML and XML
  oracles, the bounds, and clean outcomes.
- *Deep documents:* cmark's own stress inputs, through the tree path and
  =markdown->html= alike.
- *Lifetimes:* the live-handle counters (parsers, roots, render buffers) are
  zero at the end of every native suite and after every failure path; a
  document used after release signals; parse and render loops under forced
  collections; render stress; the two ABI-belief tests.
- *Every native condition but =dynamic-ffi-unavailable=* is signalled at
  least once, through a bad override or an internal wrapper redefined for
  the test.  That one needs an ECL without =:dffi=, in M4.
- *Threads* (ADR-0017): concurrent calls give what sequential ones give, on
  the inputs that race without the finish lock; many first calls at once
  start cmark once.
- *A saved image:* a child SBCL saves one, and a second child starts from it
  with nothing published, then parses.  A save while a worker holds the
  state is refused, and the worker is unharmed; an image saved with the
  save hook skipped still starts with nothing published.
- *Interrupts* (ADR-0017): a worker rendering in a loop, interrupted many
  times with a =throw=, keeps making progress, and ends with no hold and
  the counters at zero.  It runs in a child process with a time limit, so
  a deadlock fails the test instead of hanging the suite.
- UTF-8 and source positions, including a label cmark cuts inside a
  character, which becomes U+FFFD; every option through each entry point;
  and discovery both ways: the override in the container, the directory
  search in CI.

=make check-native= runs the native suite on each Lisp in =NATIVE_LISPS=
(=sbcl= by default).  It fails when no tests ran, or when the open counters
aren't zero at the end.  CCL's release binary sometimes hangs before any
Lisp code runs, so the Makefile starts CCL, for both suites and for
=make info=, through a watchdog that kills and restarts a run that hasn't
started; =make check-watchdog= tests it against a fake CCL (ADR-0013).
=make test= is =check-watchdog=, =check-purity=, =check-fixtures= and
=check-native=.  Every check is seen to fail under a targeted change.
The rules: [[file:2026-09-30-m2-native-layer-design.md][M2 design]] §8.

The five properties draw their cases from a seeded generator of our own,
and shrink a failure with our own shrinker (ADR-0020).  =make test=, and so
CI, runs each from a fixed seed with fixed case counts.  =make fuzz= runs
many more cases from a random seed, and prints a failure's seed and shrunk
input.

There is no sanitizer or Valgrind gate (ADR-0013).  M2 was to revisit that
if the counters proved too weak, and M2b added none: the counters, the
GC-pressure cycles and the render stress tests stand.  The two upstream
bugs M2b met were found by reading cmark's C and by review:
[[file:2026-09-30-m2-native-layer-design.md][M2 design]] findings 16 and 19.

CI is one amd64 job on =ubuntu-latest= in a =debian:trixie= container
(=.github/workflows/ci.yml=, ADR-0013), on pull requests and pushes to =main=.
It installs SBCL 2.5.2, ECL 24.5.10 and cmark-gfm 0.29.0.gfm.13 from Debian
(runtime packages only, so discovery sees what a user sees), and CCL 1.13 and
ocicl 2.9.0 from checksummed release downloads.  The three Lisps run in
sequence; each runs even if an earlier one fails.  Steps arrive with their
milestone: =make info= (Lisp versions, architecture, cmark-gfm version),
=check-help=, the launcher dry run, =check-vocabulary=, =check-pins= and
=check-notice= now; =make deps= and =make -k test= from M1, run even after
an earlier step fails.  From M2, =make -k test= also runs the native suite
and its oracles, with no override set, so discovery searches
=/usr/lib/x86_64-linux-gnu=: on SBCL in M2, and on CCL and ECL from M4.  The
manual macOS run records the same facts.

a local =debian:trixie= run of the CI steps, and every check has been seen to
fail.  The GitHub run waits for October, as M0's did.  Met on 2026-09-28:
226 tests on each Lisp in both places, red on a flipped fixture byte (see
=.plans/progress.md=).

*** M2 — stack-safe walks and the native layer

Parse and render with cmark-gfm on SBCL, so that no Markdown input can crash
the process by itself; the design states the remaining risk.  One design, two
slices, each with its own plan, branch and PR
([[file:2026-09-30-m2-native-layer-design.md][M2 design]]):

1. *M2a, stack-safe walks.*  Every walk over an AST or an HTML tree loops
   over an explicit stack, so memory, not the Lisp's stack, limits depth
   (ADR-0015).  No output changes.
2. *M2b, the native layer.*  CFFI bindings; finding, loading and starting the
   pinned libraries; native lifetimes; limits that keep cmark from aborting
   (ADR-0016), and a guard against cmark's footnote-entity bug (ADR-0019);
   the public =parse= and render functions (ADR-0017); a copier for every
   node kind but =:extension=, which M3 tests, and four oracles
   (ADR-0018).

Exit, for each slice:
- *M2a:* =make test= is green on SBCL, CCL and ECL.  M1's 226 tests and 28
  fixtures pass unchanged, and trees 100,000 levels deep pass through every
  walk.
- *M2b:* =make test= is green, now with the native suite on SBCL.  ASTs stay
  valid after their native document is freed, the live-handle counters are
  zero after every native suite, and the oracle passes over the whole corpus.

Both hold in the Guix container and in a local =debian:trixie= run of the CI
steps, and every check has been seen to fail.  The GitHub run waits for
October, as M0's and M1's did.

*** M3 — unknown extensions and version probes

Three deliverables, in one slice with its own plan, branch and PR
([[file:2026-10-02-m3-extensions-versions-properties-design.md][M3 design]]):

1. *Unknown-extension tests.*  No parse produces an unknown extension node
   under the pin (ADR-0008), so the tests build real ones through cmark's
   public API, with no C.  They cover the copier's =:extension= path and
   what each entry point does with an unknown node.
2. *The version cross-check.*  Startup also checks the number
   =cmark_version()= returns against the pin's, =#x001D000D=, after the
   version string (ADR-0009).
3. *The property-testing spike.*  It pitted check-it against a small
   generator of our own, on real targets.  ADR-0020 adopted property-based
   testing with our own generator and shrinker, amending ADR-0007: the
   spike found a real bug that the corpus missed (M3 finding 7).

Exit: version probes and unknown-extension behavior are tested, and
property-based testing has been evaluated.

*** M5 — release candidate

Document installation, library lookup, ECL deployment, security options, version

Exit: a clean-machine install either works or reports a clear project condition,

* Risk register

| Risk | Mitigation |
|------+------------|
| Core/extension mismatch or a second core loaded | load the pinned pair from one directory by absolute path; version check and smoke parse (ADR-0009) |
| Wrong renderer allocator | free render output only through the default allocator's =free= slot (ADR-0008) |
| ABI belief wrong (allocator slot order, =bool= width) | slot and fixture tests (ADR-0008); a reordered allocator passes the slot test, and is undefined behavior: on SBCL 2.6.4 x86-64 the native suite dies at its first render, and elsewhere it could leak silently |
| Borrowed string retained | eager copy while document is alive |
| Dynamic extension IDs | identify extensions by cached pointer, never by ID (ADR-0008) |
| ECL has no =:dffi= | early condition and static-link instructions |
| Native handle leaks into API | internal packages; AST-only parse result; live-handle counters |
| Raw HTML treated as safe HTML-tree markup | =:omit= / =:text= only, no trusted mode; link policy; serializer always escapes and validates (ADR-0010, ADR-0012) |
| Type strings missing (footnotes → ="<unknown>"=) | =classify-node= decides by type code first (ADR-0005, ADR-0008) |
| Transcribed header constants drift | checked against =vendor/cmark-gfm/src/cmark-gfm.h= (ADR-0011) |
| Pin bump changes node vocabulary | =make check-vocabulary= diffs the pinned CLI's XML |
| macOS regression between manual runs | releases gated on the manual macOS run (ADR-0001) |
| Trees deeper than the Lisp stack | no depth limit: every walk over an AST or an HTML tree loops over an explicit stack; deep tests at 100,000 levels on each Lisp (ADR-0015) |
| A small input makes cmark abort or run out of memory (padded tables, footnote references, plaintext prefixes) | three limits, each checked before cmark does the work it guards, with hard caps; rejection and soundness tests; memory pressure stays a documented risk (ADR-0016) |
| Concurrent parses race in cmark's global tables | one finish lock around =cmark_parser_finish=; thread tests on the inputs that race; another cmark-gfm user in the same process can still race (ADR-0017) |
| An interrupt, such as a timeout, unwinds out of a cmark call and leaves a malloc lock held, so the thread deadlocks | interrupts are deferred during each cmark call, so timeouts are coarse; an interrupt test in a child process with a time limit (ADR-0017) |
| cmark's footnote-entity bug: with footnotes on, a =[= followed by an entity that decodes to =^= makes cmark read past a 1-byte buffer, then use it after freeing it | an input guard rejects the pattern before any native call, with =unsupported-input=; rejection and near-miss tests; other parser bugs stay a documented risk (ADR-0019) |

* Decision log

1. CFFI is the sole implementation-independent Lisp FFI surface.
2. A narrow C shim is required for extension setup, extension metadata,
   allocator disposal, and stable ABI adaptation.  /Superseded by 14./
3. The ordinary API returns detached AST values, never cmark nodes.
4. The HTML tree (first planned as SXML; see 16) derives from the Lisp AST;
   native HTML/plaintext remain separate shell operations.
5. Version 1 has neither Lisp callbacks nor custom cmark extensions.
6. ECL's non-dynamic-FFI path is a documented deployment special case, not
   hidden non-portable reader-conditionals.
7. Linux CI only; macOS verified by hand; no Windows (ADR-0001).  CCL is
   amd64-only (amended 2026-09-27).
8. cmark-gfm pinned to 0.29.0.gfm.13 (ADR-0002).
9. ocicl for Lisp dependencies; ASDF finds them via =CL_SOURCE_REGISTRY=
   (ADR-0003).
10. Builds and tests on Guix run in a pinned, toolchain-only container
    (ADR-0004).
11. Nodes are classified by type code first; vocabulary verified against the
    pin (ADR-0005).  The shim that was to classify them is superseded by 14.
12. The =:gfm= profile enables footnotes (ADR-0006).
13. Parachute is the test framework; property-based testing is evaluated in
    M3 (ADR-0007).
14. Bind libcmark-gfm directly; no shim for now; classification in Lisp; two
    tested ABI beliefs (ADR-0008).
15. Discover the pinned pair by absolute path: override or fixed directory
    search, no bare-name =dlopen= (ADR-0009).
16. An LHTML-shaped HTML tree, not SXML; public =html-tree->string=
    (ADR-0010).
17. cmark's HTML is the tree's oracle; =vendor/cmark-gfm= submodule supplies
    the corpus (ADR-0011).
18. Raw-HTML =:omit= / =:text=, softbreak and link policies; no trusted mode
    (ADR-0012).
19. Linux CI is one amd64 job in a Debian trixie container (ADR-0013).
20. The HTML tree carries cmark's newlines; footnotes follow definition order;
    M1's fixtures are checked against the pinned CLI.  Amends 11, 16, 17
    and 18 (ADR-0014).
21. Walks loop over explicit stacks, with no depth limit; =walk-ast= is the
    one AST traversal; footnote places are keyed by owner and ordinal, not by
    path.  Amends 20 (ADR-0015).
22. Three limits keep cmark from aborting or exhausting memory:
    =*max-input-octets*=, =*max-nodes*= and =*max-output-octets*=, each
    checked before cmark does the work it guards, with hard caps (ADR-0016).
23. The public API: four entry points whose =&rest= options are checked by
    hand, defaults per function, new conditions, one re-exporting package.
    cmark starts on first use under a lock; a finish lock serializes
    =cmark_parser_finish=; the Lisps' own save hooks close the libraries; an
    alive flag guards every native access (ADR-0017).
24. The copier copies every node kind but =:extension=, takes each
    reference's label from its definition, and copies positions only with
    =SOURCEPOS=.  Four witnesses check it over the whole corpus in M2.
    Amends 11, 17, 19 and 20 (ADR-0018).  /M3 tests the =:extension= path
    too, on nodes built through cmark's public API (ADR-0018, amended)./
25. An input guard: with footnotes on, every entry point rejects a =[=
    followed by an entity that decodes to =^=, which trips a memory bug in
    cmark's parser.  It runs with the limits, before any native call, and
    signals a new condition, =unsupported-input=.  Amends 23 (ADR-0019).
26. Property-based testing is adopted, with a seeded generator and shrinker
    of our own, not check-it.  Five properties join the suites; CI runs
    them from a fixed seed with fixed case counts, and =make fuzz= from a
    random seed.  Amends 13 (ADR-0020).
