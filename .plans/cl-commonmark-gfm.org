#+title: cl-commonmark-gfm project plan
#+subtitle: Portable Common Lisp bindings for cmark-gfm
#+language: en
#+options: toc:3 num:t

* Purpose

Create =cl-commonmark-gfm=: a Common Lisp library that parses GitHub Flavored
Markdown (GFM) through [[https://github.com/github/cmark-gfm][cmark-gfm]], copies its native tree into a detached Lisp AST,
converts that AST to SXML, and exposes cmark-gfm HTML and plain-text rendering.
The initial implementation targets SBCL, CCL, and ECL on Linux and macOS,
amd64 and arm64 (ADR-0001).  It is pinned to cmark-gfm 0.29.0.gfm.13
(ADR-0002).

cmark-gfm is the syntax authority.  Lisp owns the durable AST, pure tree
operations, SXML conversion, and public API.  This is not a Markdown parser
written in Lisp.

** Success criteria

- Parse UTF-8 GFM to a Lisp value containing no native pointer; it remains valid
  after native resources are released.
- Preserve source positions and all semantic data needed for SXML, including
  core GFM extensions.
- Render HTML and plaintext with the same enabled extension set used to parse.
- Share portable Lisp sources across SBCL, CCL, and ECL.
- Keep foreign calls, library loading, allocation, and cleanup in a small
  imperative shell; keep AST manipulation and SXML conversion functional.

** Non-goals for version 1

- Writing or registering custom cmark syntax extensions from Lisp.
- Exposing mutable =cmark_node *= values through the ordinary API.
- A lossless Markdown formatter/editor model.
- Reimplementing cmark-gfm HTML rendering in Lisp.
- Downloading or compiling C dependencies when the Lisp system is loaded.
- Windows (ADR-0001).

* Core architectural decision

** Functional core, imperative shell

#+begin_example
Markdown
   |
   v
imperative shell: encode -> parse -> traverse/copy -> release
   |
   v
functional core: AST -> transform AST -> SXML
   |
   +--> imperative shell: parse -> render -> copy -> free
#+end_example

The parser operation necessarily allocates native state and can signal a
loading/ABI error.  Its high-level interface is still value-oriented:
=parse= returns a fresh, detached AST or signals a project condition.  It never
returns a live cmark handle.

The core gets and returns ordinary Lisp values only.  It is deterministic,
portable, straightforward to test without native libraries, and suitable for
persistent-style rewrite functions.  The shell owns native lifetimes and
concentrates all effects in one reviewable place.

** Systems and packages

| System/package | Role | Public |
|----------------+------+--------|
| =cl-commonmark-gfm/ast= | AST constructors, predicates, queries, pure rewrites | yes |
| =cl-commonmark-gfm/sxml= | pure AST-to-SXML conversion | yes |
| =cl-commonmark-gfm/ffi= | CFFI declarations and raw private handles | no |
| =cl-commonmark-gfm/native= | native loading, initialization, resource scopes | no |
| =cl-commonmark-gfm= | convenient parse/render API | yes |
| =cl-commonmark-gfm/tests= | pure and native integration tests | test only |

The AST and SXML systems must load and pass their tests without any C library
present.  This requirement is the mechanical enforcement of the
functional-core boundary.

** Lisp dependencies and development environment

- ocicl acquires Lisp dependencies (CFFI, the test framework).  =ocicl.csv= is
  committed; =ocicl/= is not (ADR-0003).
- Tests locate systems through ASDF's =CL_SOURCE_REGISTRY=, never through an
  rc file or =ocicl-runtime.lisp=, so SBCL, CCL and ECL load identically and a
  missing system fails instead of downloading mid-test.
- On Guix, every build and test runs in the pinned container
  (=scripts/guix-env=, ADR-0004).  It carries the three Lisps, cmark-gfm
  0.29.0.gfm.13, a C toolchain and a from-source ocicl, and nothing from the
  host's =HOME=.  =make check-guix= verifies it.

** AST contract

Use a compact, immutable-by-convention representation.  A suitable initial
implementation is a =node= structure whose constructor is private and whose
public package exports no mutators:

#+begin_src lisp
(defstruct (node (:constructor %make-node))
  (kind nil :type keyword :read-only t)
  (attributes nil :type list :read-only t) ; canonical plist
  (children nil :type list :read-only t)   ; proper list of NODE
  (sourcepos nil :type (or null sourcepos) :read-only t))
#+end_src

The representation is not the public promise.  The promise is constructors,
predicates, read-only queries, structural equality, and pure transforms.  This
permits a later move to specialized node structures without an API break.

Use stable Lisp keywords, not cmark's integer node IDs or type strings.  The
vocabulary below was verified against cmark-gfm 0.29.0.gfm.13 (ADR-0005;
=tests/fixtures/vocabulary.md=, =make check-vocabulary=).

Notes from verification:

- There is no autolink node kind: the autolink extension emits =:link=.
- Footnotes are enabled by the option =CMARK_OPT_FOOTNOTES=, not by a syntax
  extension.  Footnote numbering is computed in Lisp; the AST carries labels.
- =custom_block= / =custom_inline= never come from parsing and are not in the
  vocabulary; meeting one signals =unsupported-extension-node=.

*** Source positions

Copy source positions as
=((start-line . start-column) . (end-line . end-column))=, or =nil= when
cmark reports none (email autolinks, for one).  They are reported as-is and
never repaired: cmark emits end-before-start ranges, zero end columns and
children that start before their parent.  cmark's columns are bytes; the API
must not imply Unicode grapheme-column semantics.

Unknown extension nodes must not disappear.  Represent a recognized but
otherwise unsupported extension as =:extension= with its extension name, type
string, source position, safely copied attributes, and children.  If even that
cannot be represented safely, signal =unsupported-extension-node=.

* FFI architecture

** CFFI is the portable Lisp frontend

CFFI is the one Lisp FFI API used by the project.  cmark-gfm's public API is
well suited to it: opaque pointers, scalar integers, =size_t=, and byte
strings.  No version-1 operation needs a callback, a variadic function, or a C
structure passed or returned by value.

Use exact ABI types:

- =size_t= becomes CFFI =:size=.
- C option bitsets use an explicit unsigned 32-bit CFFI type.
- C boolean-like =int= is explicitly decoded to Lisp =t=/=nil=.
- UTF-8 source is an octet vector plus its byte length, never a Lisp character
  count.
- The portable sources do not use =sb-alien=, CCL-specific foreign APIs, or
  ECL's =ffi:= package.

** A narrow C shim

Bind a small project-owned library, =libcl-commonmark-gfm-shim=.  It is compiled
against one pinned cmark-gfm header set and linked with cmark-gfm's core and
extension libraries.  It is an ABI adapter, not another Markdown parser.

The shim owns the parts that are needlessly hazardous to expose through CFFI:

- registration/attachment of cmark-gfm core extensions;
- construction and retention of the HTML renderer extension list;
- disposal of cmark-owned renderer buffers through the correct allocator;
- classifying each node into a stable project kind (ADR-0005);
- wrapping the GFM metadata accessors (public in
  =cmark-gfm-core-extensions.h=) for table alignment and task state;
- cmark-version and build-compatibility probes.

Classification uses =cmark_node_get_type= for nodes without an extension and
the extension name plus type string only for extension nodes.  Type strings
alone are not enough: in 0.29.0.gfm.13 =cmark_node_get_type_string= returns
="<unknown>"= for both footnote kinds.

This avoids exposing =cmark_llist=, allocator structures, extension private
data, dynamically assigned extension node IDs, and C callbacks in Lisp.  Do
not bind cmark internal headers or inspect C structure fields from Lisp.

Suggested ABI:

#+begin_src c
typedef struct cl_cmark_document cl_cmark_document;
typedef struct cl_cmark_bytes cl_cmark_bytes;

int cl_cmark_initialize(void);
const char *cl_cmark_version(void);
const char *cl_cmark_build_version(void);

int cl_cmark_parse_gfm(const uint8_t *source, size_t length,
                       uint32_t options, uint32_t extensions,
                       cl_cmark_document **out);
void cl_cmark_document_free(cl_cmark_document *document);

void *cl_cmark_document_root(cl_cmark_document *document);
void *cl_cmark_node_first_child(void *node);
void *cl_cmark_node_next(void *node);
int cl_cmark_node_kind(void *node);           /* stable CL_CMARK_KIND_* */
const char *cl_cmark_node_extension_name(void *node); /* NULL if none */
const char *cl_cmark_node_type_string(void *node);    /* for :extension */
/* Scalar/string accessors for every copied AST attribute. */

int cl_cmark_render_html(cl_cmark_document *, uint32_t options,
                         cl_cmark_bytes **out);
int cl_cmark_render_plaintext(cl_cmark_document *, uint32_t options,
                              int width, cl_cmark_bytes **out);
const uint8_t *cl_cmark_bytes_data(const cl_cmark_bytes *);
size_t cl_cmark_bytes_length(const cl_cmark_bytes *);
void cl_cmark_bytes_free(cl_cmark_bytes *);
#+end_src

The document handle owns the finished cmark root and its renderer extension
list.  Lisp frees the document once rather than freeing a root and a list
separately.  This makes double-free and mismatched-renderer-extension bugs
harder to express.

The shim must explicitly register the core GFM extensions and attach the
selected set to each parser.  The default =:gfm= profile comprises tables,
strikethrough, autolinks, tag filter, and task lists, plus the
=CMARK_OPT_FOOTNOTES= option (ADR-0006).  An extension selection is
also retained for HTML rendering.  Tag filter changes HTML rendering only; the
AST still holds the filtered raw HTML (ADR-0005).


** Ownership protocol

The normal parse path is:

#+begin_src lisp
(defun parse (markdown &key profile extensions sourcepos)
  (let ((bytes (utf8-octets markdown))
        (options (make-parse-options :profile profile
                                     :extensions extensions
                                     :sourcepos sourcepos)))
    (with-native-document (document bytes options)
      (copy-native-tree (native-root document)))))
#+end_src

=make-parse-options= is the pure validation step described under "Option
objects"; invalid choices fail before any native call.

=with-native-document= is an internal =unwind-protect= resource scope.  It
releases the document exactly once on success, condition, and non-local exit.
=copy-native-tree= eagerly copies every string and scalar, then returns a pure
AST.

Ownership rules:

- A native node is borrowed from its document and dies with that document.
- A C string returned from cmark/shim is borrowed; convert it before freeing
  the document or issuing an operation that may invalidate it.
- A returned renderer buffer is owned by its =cl_cmark_bytes= handle.  Copy the
  reported length, then call only =cl_cmark_bytes_free=.
- Never call =cffi:foreign-free= on cmark-owned output.  The wrong allocator
  can corrupt the heap.
- Retain the UTF-8 octet vector for the entire foreign call.  A raw address may
  not outlive its dynamic pointer scope.
- Null is an optional value only where the shim contract says so; elsewhere it
  becomes a typed condition before any accessor call.
- A finalizer may be an emergency leak backstop, never normal cleanup.

** Initialization and loading

Initialization is process-global, idempotent, and guarded by a lock around its
first call.  It completes before constructing a parser.

Library-resolution order:

1. application-supplied =*native-library-pathname*=;
2. documented environment configuration;
3. ASDF-relative packaged artifacts, if supplied;
4. CFFI platform conventional names.

Load cmark-gfm core, cmark-gfm extensions, then the shim.  Link the shim with
appropriate runtime search-path metadata so it resolves the exact core/extension
pair it was built against.

Guix's glibc searches no FHS directory, so on a Guix host step 4 resolves
only with =LD_LIBRARY_PATH= set; the development container sets it
(ADR-0004).

At startup, compare the shim build version with the runtime cmark-gfm version.
Reject an out-of-range combination.  Then run a small smoke parse containing a
table and task item; this verifies extension linkage/registration rather than
merely proving a similarly named core library loaded.

* Runtime-specific CFFI behavior

** Shared policy

Do not make CFFI Groveler a required user load-time dependency in version 1.
It would require a C toolchain and headers merely to load Lisp.  The narrow shim
is compiled against pinned headers; version probes plus integration tests guard
against ABI drift.  A Groveler-based developer check may be added later.

No reader conditionals belong in AST or SXML code.  If a loader workaround is
needed, confine it to =native= and cover it with an integration test.

** SBCL

SBCL is the initial development target.  Standard CFFI dynamic loading supports
the required opaque-pointer API.  It may also support statically linked
deployment, but that is an application delivery mode, not a library assumption.

- Do not use =sb-alien= in library sources.
- Do not rely on finalizer timing or a GC run for native cleanup.
- Keep source octets live for every call and do not retain raw addresses.
- Version 1's no-callback policy avoids callback support differences.

** CCL

CCL uses CFFI through its implementation backend; it needs no separate FFI
definitions for this API.  The major practical risk is dynamic-loader
configuration, especially macOS install names and extension-library discovery.

- Exercise both CFFI's name lookup and explicit absolute shim pathname, in
  Linux CI and in the manual macOS run (ADR-0001).
- Do not retain implementation-owned string storage across a foreign call.
- Keep all loader branches inside the native shell; AST/SXML code stays
  completely shared.

** ECL

ECL supports CFFI dynamic loading when =:dffi= is present.  On ECL builds
without it, CFFI's normal =load-foreign-library= route cannot load a library.

- Detect missing =:dffi= and signal =dynamic-ffi-unavailable= with static-link
  instructions rather than a generic unresolved-library failure.
- Document a deployment path that links the shim and cmark-gfm into the ECL
  application, then uses ECL's supported static foreign-library mechanism.
- Maintain a dynamic ECL integration job and, after it stabilizes, a compiled
  static-link smoke test.
- The pure core continues to load and test with no ECL FFI configuration.

** Initial support matrix

| Runtime | Linux (CI) | macOS (manual, maintainer's laptop) |
|---------+------------+-------------------------------------|
| SBCL | required | required |
| CCL | required on amd64 | required |
| ECL with dynamic FFI | required | required |
| ECL static deployment | documented/tested | documented/tested |

Windows is not supported (ADR-0001).  CI runs on Linux only; there are no

Do not call a release portable until each required cell builds the same pinned
core/extensions/shim set and passes native integration tests.

* C safety and security

** ABI and memory safety rules

- Pin a cmark-gfm release/source revision and build shim, core, and extensions
  together.  Do not call an arbitrary system cmark library supported.
- No Lisp dereference of a cmark structure: all C structures remain opaque.
- Check every status and pointer result before access.
- Use =size_t= end-to-end and reject an encoded input that cannot fit it.
- Copy output through explicit buffer lengths where the shim provides one.
- Do not allow C callbacks into Lisp in v1: that avoids foreign-thread entry,
  callback rooting/lifetime, and exceptions crossing C frames.
- Do not expose cmark mutation functions in v1.  The AST is a read model; C
  mutation creates aliasing and ownership cases without serving the goal.
- Run an AddressSanitizer/UndefinedBehaviorSanitizer native build in CI where
  supported.

** Rendering policy

cmark-gfm's default HTML behavior treats raw HTML and unsafe link schemes
safely; =CMARK_OPT_UNSAFE= deliberately turns that off.  The Lisp API exposes
this only as =:unsafe-html nil= and never enables it by default.

SXML is a separate security boundary.  It must make raw HTML explicit:

- =:raw-html :preserve= yields a tagged non-executable value for a downstream
  renderer that knowingly handles it.
- =:raw-html :drop= omits it.
- =:raw-html :text= emits literal text.

Never inject raw HTML as ordinary SXML.  Apply a separately configurable URL
policy during SXML conversion; a copied AST is not a sanitized AST.  The
=tagfilter= extension does not help here: it changes cmark's HTML output only,
and the AST keeps =<script>= blocks verbatim.

** Conditions

| Condition | Meaning |
|-----------+---------|
| =native-library-not-found= | core/extensions/shim could not be loaded |
| =native-abi-mismatch= | shim and runtime cmark-gfm versions disagree |
| =dynamic-ffi-unavailable= | ECL requires its static deployment route |
| =native-initialization-error= | registration or extension smoke parse failed |
| =native-parse-error= | a document could not be produced |
| =native-render-error= | a renderer could not produce a buffer |
| =unsupported-extension-node= | no safe semantic AST mapping exists |
| =invalid-render-option= | options are incompatible or in the wrong API |

These conditions include operation, library versions, and shim diagnostics.
Raw CFFI errors are implementation details, not the routine public vocabulary.

* Functional AST and SXML

** Option objects

Validate a pure Lisp option object before entering the native shell.  It
contains a cmark option bitset, selected extensions, and source-position
policy.  Invalid names or incompatible choices fail before parsing.

The default =:gfm= profile attaches core GFM extensions and enables footnotes.
=:commonmark= attaches none and leaves footnotes off.  Store the selected profile/extensions in document metadata so consumers
can distinguish syntax that did not match from an extension that was disabled.

** Native-to-Lisp copier

=copy-native-tree= is the sole impure AST stage.  It walks the native tree
depth-first through shim accessors, copies values, normalizes the type string,
and returns a pure tree.  It has a tested case for every supported cmark and
core-GFM node type.

Its default behavior is not data loss: emit =:extension= if it can safely
identify the foreign extension; otherwise signal =unsupported-extension-node=.

** SXML contract

=ast->sxml= is pure and does no FFI.  Use normal SXML shape:

#+begin_example
(:tag (@ (:attribute "value")) child ...)
#+end_example

A document yields a top-level list by default, avoiding an invented wrapper
element.  =:document-wrapper= supplies one when desired.

| AST | SXML |
|-----+------|
| =:paragraph= | =(:p ...)= |
| =:heading= | =(:h1 ...)= through =(:h6 ...)= |
| =:link= | =(:a (@ (:href "...") (:title "...")) ...)= |
| =:table= | =(:table ...)=: =:thead= wraps the =:table-header= row, =:tbody= the =:table-row= rows |
| =:task-item= | =(:li (@ (:class "task-list-item")) ...)= |
| footnotes | numbered in Lisp by first reference; shape settled in M1 |
| =:softbreak= | explicit newline/space/=(:br)= policy |
| raw HTML | one of the explicit raw-HTML policies |

SXML is a structural conversion and need not byte-match cmark HTML.  Native
HTML rendering is the compatibility route.

* Public API sketch

#+begin_src lisp
(parse markdown &key profile extensions sourcepos)
;; string -> document AST

(ast->sxml document &key raw-html softbreak document-wrapper link-policy)
;; AST -> SXML tree/list

(markdown->sxml markdown &rest parse-and-sxml-keys)
;; string -> SXML tree/list

(markdown->html markdown &key profile extensions sourcepos unsafe-html)
;; string -> string

(markdown->plaintext markdown &key profile extensions width)
;; string -> string

(map-ast function document)
(fold-ast function initial-value document)
(transform-ast function document)
;; pure structural utilities
#+end_src

Do not silently ignore renderer options.  Passing SXML-only options to
=markdown->html= signals =invalid-render-option=.

* Build, testing, and release

** Native dependency policy

Phase 1 supports an externally installed cmark-gfm development package plus a
project-built shim.  The package must report the pinned version (ADR-0002):
the Guix container provides it on Linux; the maintainer's macOS install is
checked by hand.  Build checks must verify headers, core library, extension
library, and compatible version separately.  Failing clearly is preferable to
silently linking plain cmark.

Phase 2 may provide reproducible bundled-source artifacts, pinned to a specific
upstream revision and recording compiler/architecture/library version.  It
supplements; it does not replace; the external-library path.

** Tests

Tests use Parachute (ADR-0007), installed through ocicl.  Each suite runs with
the quiet reporter and turns the result into the process exit code, so CI and
=make= see failures without parsing output.

Pure tests:

- AST construction/query/rewrite invariants and structural equality.
- SXML snapshots for every standard and GFM node.
- Raw HTML, soft-break, and URL-policy tests.
- Repeated SXML conversion is =equal= and no public tree contains a foreign
  pointer.

Native integration tests:

- UTF-8 and source positions; boundary-sized sources and embedded NUL behavior.
- Tables, strikethrough, autolinks, tag filtering, checked/unchecked task items.
- HTML/plaintext rendering with the exact parsing extension profile.
- Repeated parse/render cycles under GC pressure.
- Missing library, ABI mismatch, initialization, and unsupported-node conditions.
- Sanitizer build for native code where available.

Every Linux CI job, and the manual macOS run, must build/install the pinned
core/extensions, build the shim, load through the normal CFFI path, run
pure/native tests, and record Lisp implementation, architecture, shim build
version, and runtime cmark version.

** Milestones

*** M0 — design freeze

write the shim header and complete AST vocabulary table.

justified by observed differences.

Document installation, library lookup, ECL deployment, security options, version
compatibility, and support matrix.

never an invalid-free crash or unexplained unresolved symbol.

* Risk register

| Risk | Mitigation |
|------+------------|
| Core/extension mismatch | build and smoke-test them as a versioned pair |
| Wrong renderer allocator | only shim frees renderer buffers |
| Borrowed string retained | eager copy while document is alive |
| Dynamic extension IDs | type names, shim metadata, pinned compatibility tests |
| ECL has no =:dffi= | early condition and static-link instructions |
| Native handle leaks into API | internal packages; AST-only parse result |
| Raw HTML treated as safe SXML | explicit raw-HTML and link policies |
| Broad binding becomes ABI burden | narrow shim; no C structure layouts |
| Type strings missing (footnotes → ="<unknown>"=) | shim classifies by type code first (ADR-0005) |
| Pin bump changes node vocabulary | =make check-vocabulary= diffs the pinned CLI's XML |
| macOS regression between manual runs | releases gated on the manual macOS run (ADR-0001) |

* Decision log

1. CFFI is the sole implementation-independent Lisp FFI surface.
2. A narrow C shim is required for extension setup, extension metadata,
   allocator disposal, and stable ABI adaptation.
3. The ordinary API returns detached AST values, never cmark nodes.
4. SXML derives from the Lisp AST; native HTML/plaintext remain separate shell
   operations.
5. Version 1 has neither Lisp callbacks nor custom cmark extensions.
6. ECL's non-dynamic-FFI path is a documented deployment special case, not
   hidden non-portable reader-conditionals.
7. Linux CI only; macOS verified by hand; no Windows (ADR-0001).
8. cmark-gfm pinned to 0.29.0.gfm.13 (ADR-0002).
9. ocicl for Lisp dependencies; ASDF finds them via =CL_SOURCE_REGISTRY=
   (ADR-0003).
10. Builds and tests on Guix run in a pinned, toolchain-only container
    (ADR-0004).
11. The shim classifies nodes by type code; vocabulary verified against the
